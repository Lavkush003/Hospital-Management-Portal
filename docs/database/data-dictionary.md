# Data Dictionary

This dictionary describes every Prisma model and scalar field in the Hospital Management
System database. PostgreSQL table and enum names are quoted PascalCase identifiers; the
document uses the Prisma names for readability.

## Type conventions

| Convention       | Meaning                                                              |
| ---------------- | -------------------------------------------------------------------- |
| `text`           | PostgreSQL variable-length text with no application-level length cap |
| `varchar(n)`     | PostgreSQL character varying with an explicit maximum length         |
| `timestamptz(3)` | Timestamp with time zone, millisecond precision                      |
| `time(0)`        | Time of day without time zone, second precision                      |
| `numeric(p,s)`   | Exact decimal with precision `p` and scale `s`                       |
| `jsonb`          | Binary JSON document                                                 |
| `cuid()`         | Collision-resistant string identifier generated by Prisma            |
| `UQ`             | Unique constraint or unique index                                    |
| `FK`             | Foreign key                                                          |
| `PK`             | Primary key                                                          |
| `@updatedAt`     | Prisma updates the field on every write                              |
| `now()`          | PostgreSQL current transaction timestamp                             |

All monetary values use `numeric(12,2)`. All application timestamps use
`timestamptz(3)` so they remain unambiguous across server and client time zones.

## User

Stores authentication identities and role assignments. A user may be linked to at most one
doctor profile and at most one staff profile.

| Field          | Database type    | Attributes / default | Description                                                  |
| -------------- | ---------------- | -------------------- | ------------------------------------------------------------ |
| `id`           | `text`           | PK, `cuid()`         | Primary identifier                                           |
| `email`        | `varchar(320)`   | UQ, lower-email UQ   | Login email; stored as entered but unique case-insensitively |
| `passwordHash` | `varchar(255)`   | Required             | bcrypt password hash; never returned by APIs                 |
| `role`         | `UserRole`       | Required             | Authorization role                                           |
| `status`       | `UserStatus`     | Default `ACTIVE`     | Account lifecycle status                                     |
| `firstName`    | `varchar(100)`   | Required             | Given name                                                   |
| `lastName`     | `varchar(100)`   | Required             | Family name                                                  |
| `phone`        | `varchar(32)`    | Nullable             | Contact telephone number                                     |
| `lastLoginAt`  | `timestamptz(3)` | Nullable             | Most recent successful login                                 |
| `createdAt`    | `timestamptz(3)` | Default `now()`      | Creation timestamp                                           |
| `updatedAt`    | `timestamptz(3)` | `@updatedAt`         | Last update timestamp                                        |

Indexes: `(role, status)`, `(lastName, firstName)`. Unique exact email plus unique
`lower(email)`.

## IdempotencyKey

Stores request deduplication state for mutating API operations. A completed record returns
the original resource identifier on replay. A failed operation rolls back both the
business mutation and this record because they share one transaction.

| Field                | Database type       | Attributes / default        | Description                                  |
| -------------------- | ------------------- | --------------------------- | -------------------------------------------- |
| `id`                 | `text`              | PK, `cuid()`                | Primary identifier                           |
| `actorUserId`        | `text`              | FK                          | User initiating the operation                |
| `scope`              | `varchar(100)`      | Required                    | Operation scope, such as `appointments.book` |
| `key`                | `varchar(200)`      | Required                    | Client-supplied idempotency key              |
| `requestHash`        | `varchar(64)`       | Required                    | SHA-256 hash of the canonical request body   |
| `status`             | `IdempotencyStatus` | Default `PENDING`           | Processing state                             |
| `resourceType`       | `varchar(100)`      | Nullable                    | Type of created or changed resource          |
| `resourceId`         | `varchar(64)`       | Nullable                    | Resource identifier for replay               |
| `responseStatusCode` | `integer`           | Nullable, `100..599`        | HTTP status to replay                        |
| `responseBody`       | `jsonb`             | Nullable                    | Cached response body                         |
| `expiresAt`          | `timestamptz(3)`    | Required, after `createdAt` | Expiry timestamp                             |
| `createdAt`          | `timestamptz(3)`    | Default `now()`             | Creation timestamp                           |
| `updatedAt`          | `timestamptz(3)`    | `@updatedAt`                | Last update timestamp                        |

Unique: `(actorUserId, scope, key)`. Indexes: `(expiresAt)`, `(status, expiresAt)`,
`(resourceType, resourceId)`.
CHECKs: `IdempotencyKey_expiry_check`, `IdempotencyKey_response_status_check`.
